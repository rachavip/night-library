# 夜读 · NAS 电子书馆

部署在 NAS 上的私人网页版电子书管理系统。刮削本地文件夹、按书名/作者/格式/时间排序、直接在浏览器里阅读。界面是「夜读书房」：深墨蓝底、暖纸色文字、一束琥珀灯光。

## 飞牛 NAS 部署（已按你的路径配好）

compose 文件放在 `/vol1/1000/docker/ebooks`（项目目录），你的电子书在 `/vol1/1000/EBook`（书籍目录，两者不同）。`docker-compose.yml` 里的挂载路径已经写好，不需要再改参数：

```yaml
- /vol1:/vol1:ro        # 整个 vol1 挂进容器且路径一致，网页里就能添加任意书籍文件夹
- ./data:/app/data      # 索引/封面/缓存/进度
```

环境变量 `BOOKS_DIR: /vol1/1000/EBook` 是默认书籍文件夹（你的电子书放在这里）。容器名 `ebooks`，访问端口 `8080`。

> 为什么挂整个 `/vol1`：这样网页设置里填的 NAS 路径（如 `/vol1/1000/小说`）在容器内也真实存在，刮削才能找到文件。全程只读，不会改动你的原书。

### 方式一：GitHub 镜像，一键部署（推荐）

把镜像发布到自己的 GitHub Container Registry 后，NAS 上只需要一个 `docker-compose.yml`，不用上传源码：

1. 按 **[DEPLOY_GITHUB.md](DEPLOY_GITHUB.md)** 把代码推到 GitHub，等 Actions 构建出镜像
2. 把项目里的 `docker-compose.yml` 上传到 `/vol1/1000/docker/ebooks`
3. `image:` 已填好你的镜像地址 `ghcr.io/rachavip/night-library:latest`，无需再改
4. 执行：

   ```bash
   cd /vol1/1000/docker/ebooks
   docker compose pull
   docker compose up -d
   ```

以后更新只要 `git push`，再到 NAS 上 `docker compose pull && docker compose up -d` 即可。

### 方式二：本地构建（不经过 GitHub）

把整个项目文件夹（含 `docker-compose.build.yml`、`Dockerfile`、`server/`、`public/`、`scripts/`、`package.json`、`package-lock.json`）上传到 `/vol1/1000/docker/ebooks`，然后：

```bash
cd /vol1/1000/docker/ebooks
docker compose -f docker-compose.build.yml up -d --build
```

**国内网络拉包慢？用国内源版**：`Dockerfile.cn` 把 apt 换成阿里云、npm 换成 npmmirror（含 `package-lock.json` 里 169 个下载地址一并替换），功能与默认版完全一致：

```bash
cd /vol1/1000/docker/ebooks
docker compose -f docker-compose.cn.yml up -d --build
```

对应的 compose 文件是 `docker-compose.cn.yml`，端口同样是 `8421:8080`。上传源码时记得带上 `Dockerfile.cn` 和 `docker-compose.cn.yml`。

### 方式三：飞牛 Docker 图形界面

「Docker」→「项目」→「创建项目」，项目路径选 `/vol1/1000/docker/ebooks`，compose 文件选目录里的 `docker-compose.yml`，点部署。镜像方式在图形界面里最顺；本地构建请用方式二。

> 首次构建或拉取会安装/下载 Calibre（用于 MOBI/AZW3 转换），镜像较大、耗时几分钟，属正常现象。

### 放书的位置 / 添加电子书文件夹

默认刮削 `/vol1/1000/EBook`。要把 NAS 上其他位置的书也收进来，不用改 compose、不用重建容器：

1. 点右上角 **⚙** →「电子书文件夹」
2. 填 NAS 上的绝对路径，例如 `/vol1/1000/小说`，点「添加」（会先检查容器内能否访问）
3. 点「保存设置」——文件夹有变化时会自动刮削，也可以手动点顶部「刮削」

可以添加多个文件夹，移除后保存同样会重新刮削。扫描器会自动跳过 `data/`、`node_modules/` 等项目目录，不会把索引和缓存误扫成书。

### 自动刮削（新增）

往 NAS 文件夹里放了新书不用点「刮削」——系统会自动发现：

- **每次启动刮一次**：默认开启。启动后网页立刻能打开（先用上次的索引），新书在后台刮削完成后书架会自动刷新，不用手动 F5。
- **定时刮削**：默认每 **60 分钟**一次。书架上方会显示「每 60 分钟自动整理 · 下次 HH:MM」。
- **改刮削时间不用动 compose**：进 ⚙ → 自动刮削，勾选「每次启动时刮削一次」，在「每隔多少分钟刮削」填数字（例如 `15`），保存后立即生效。书架上方会同步显示「每 15 分钟自动整理 · 下次 HH:MM」。
- 间隔填 `0` 就关掉定时，只在启动和手动点击「刮削」时触发。启动开关要下次重启才生效，界面上有标注。
- 手动刮削与自动刮削共用一把锁，不会重叠跑；自动刮完会弹一条「书房已更新，新增 N 册」。
- compose 里的 `SCAN_ON_START` / `SCAN_INTERVAL_MINUTES` 只在你想强制固定调度时才取消注释，会覆盖网页设置；日常保持注释即可。

> 添加前确认该路径确实在 `/vol1` 下面（因为只挂了 `/vol1`）。如果你的书在其他存储池（如 `/vol2`），把 compose 里的挂载再加一行 `- /vol2:/vol2:ro` 并重新 `docker compose up -d` 即可。

## 版本号与更新检测

主页副标题后面有一个版本徽标（如「当前版本：0.5」），点开能看到更新日期、本次改动，以及「检查更新」。

- **版本号从哪来**：项目根目录的 `version.json`。它是唯一来源——页面显示、更新检查都读它。当前是 **当前版本：0.5**。
- **维护规则（固定）**：每次修改程序后，`version.json` 里的 `version` **自动 +0.1**（`0.4` → `0.5` → `0.6` …），并在 `notes` 里写一句话说明这次改了什么、`date` 更新为当天。文件随代码一起打包进镜像，所以 NAS 上显示的版本就是它实际运行的代码版本。
- **页面自动提示**：打开页面后会后台自动检查一次更新（30 分钟内只查一次，失败静默）。发现 GitHub 上有更新时，版本徽标会亮起琥珀色并带一个小圆点，点开即可看到详情——不用每次手动点「检查更新」。
- **怎么判断是不是最新**：点版本徽标 →「检查更新」。它会拿你正在运行的版本和 GitHub 仓库 `version.json` 对比，给出三种结果：
  - **已是最新版** — 运行的代码和 GitHub 上上传的一致。
  - **GitHub 上是当前版本：N** — 说明有改动已上传但你还没重建/拉取镜像，按部署步骤更新即可。
  - **本机比 GitHub 新** — 说明本地改了但还没上传文件到 GitHub（正是"上传的文件是不是最新"的检查）。
- 检查会先试 GitHub raw，失败再试 jsDelivr；两个都连不上时会提示手动去仓库看，不影响正常使用。

## 书房设置（改名 / 主题 / 背景 / 音乐）

点右上角 **⚙** 打开设置抽屉，改完点「保存设置」。

- **电子书文件夹**：增删要刮削的 NAS 书籍目录，添加时校验路径，保存后自动刮削（详见上文）。
- **名称**：系统名称与副标题可改，书架标题、页签和阅读器的返回按钮会同步更新。
- **主题**：夜读（墨蓝+琥珀，默认）、纸笺（浅色）、墨影（近黑+香槟金）、青屿（深青+薄荷绿）。
- **背景图片**：可以「选择本地图片」上传，或填书籍目录里图片的相对路径（例如 `壁纸/书房.jpg`）。暗度和虚化可拖动调节，暗度会把背景压暗以保证文字可读；「清除」后记得保存。上传的图片存在 `data/backgrounds/`。
- **音乐**：默认「网页嵌入」模式，已预填你的 AnyListen 地址 `http://192.168.0.111:9500`，**compose 里不用做任何配置**。设置里还能给 music-dl、Songloft、MelodyHub、Solara 光域填地址，在播放器左上角一键切换。收起面板后音乐继续播放。

### 音乐地址说明（两种改法，按需要选）

程序里已预填你的地址 `http://192.168.0.111:9500`，**你自己用的时候 compose 里什么都不用填**，部署后直接能听。

1. **网页里改（你自己的日常用法）**：进 ⚙ → 音乐 → 给对应服务填「地址」（需要登录的再填「登录页地址」），点「设为当前」后保存。重启也不丢，不用动 compose。
2. **compose 里改（分享给别人时用）**：如果对方不知道要在网页哪里改地址，就把 `docker-compose.yml` 里这两行的注释打开、换成自己的地址：

   ```yaml
   MUSIC_URL: http://192.168.1.20:9500
   MUSIC_MODE: embed
   ```

   然后 `docker compose up -d` 即可生效，不用重新构建镜像。

**优先级**：compose 的 `MUSIC_URL` > 网页保存值 > 程序默认值。所以 compose 一旦填写就会覆盖网页里的设置；不填则由网页设置或默认值决定。

> compose 里的可选配置项都是这个思路——**用到哪个才加哪个**，没用到的保持注释或不写即可，不影响部署。

### 音乐 · 网页嵌入（默认）

设置里选 **网页嵌入**，可给 5 个服务填地址：AnyListen（已预填）、music-dl、Songloft、MelodyHub、Solara 光域。地址填完整 URL（如 `http://192.168.0.111:9500`），点「测试当前服务」会同时告诉你能不能嵌入、是否可能需要登录。

- **切换**：填了地址的服务会出现在播放器左上角的下拉里，选中即切换，不用回设置页。
- **需要登录的服务**：在「登录页地址」填登录入口；打开 ♫ 后顶部会出现提示，可以「打开登录页」，登录完回来点「重新加载」。登录状态由浏览器保存，同一个浏览器、同一个服务地址才会生效。
- **嵌入被拒绝**：有些站点用 `X-Frame-Options` 或 CSP 禁止被嵌入。测试时会提示「嵌入受限」，打开后播放器顶部也会给出「新窗口打开」按钮——这是最稳的兜底，音乐照常播放。
- **加载失败**：连接超时或服务没启动时会显示明确错误，可重试或打开设置；网络抖动会自动重试两次。
- 浏览器直连音乐服务，不经过本服务代理；地址必须是你浏览器能访问到的 IP 和端口。
- 若本系统改用 HTTPS 而音乐服务仍是 HTTP，浏览器会因「混合内容」拦截内嵌页面——两边保持同为 HTTP，或给音乐服务也配 HTTPS。

### 音乐 · 随机播放（Subsonic）

在设置里切换为 **随机播放**，兼容 Navidrome、Airsonic、Gonic 等：
- 服务地址填 `IP:端口`，例如 Navidrome 默认 `192.168.1.10:4533`（不用写 `http://`）
- 填写用户名和密码；密码只保存在容器内的 `data/settings.json`，接口返回时会打码
- 浏览器不直连音乐服务，由本服务代理，避开跨域问题
- ♫ 会拉取 50 首随机歌曲打乱播放，支持上一首/下一首/暂停/音量；歌放完自动切下一首

## 格式支持

| 格式 | 网页阅读 | 说明 |
| --- | --- | --- |
| PDF | ✅ | pdf.js 逐页渲染，支持进度与四种缩放：匹配宽度 / 匹配页面 / 匹配可见 / 实际大小 |
| EPUB | ✅ | epub.js 渲染，支持章节跳转与字号 |
| TXT | ✅ | 自动识别 UTF-8 / GB18030，按视口重新分页 |
| MOBI | ✅ | 由镜像内的 Calibre 转为 EPUB 后阅读，转换结果缓存 |
| AZW3 | ✅ | 同上 |

MOBI / AZW3 的转换只发生在第一次打开时，之后走缓存。转换文件写在 `data/converted/`，不会碰你的原始书籍（书籍目录以只读方式挂载）。

EPUB / MOBI / AZW3 都通过带 `.epub` 后缀的地址交给 epub.js（`/api/book/:id/read.epub`）。epub.js 是**靠 URL 后缀**判断「这是一个压缩包」还是「一个已解压的目录」的：地址以 `/read` 结尾（没有后缀）时它会当成目录，转去请求 `META-INF/container.xml`，那个地址在服务端并不存在，于是整本书直接打不开。

另外 epub.js 自己不打包 zip 解压器，页面里必须有一个全局 `JSZip`，否则报 `JSZip lib not loaded`。所以 `public/vendor/` 下这四个文件缺一不可：`pdf.min.js`、`pdf.worker.min.js`、`jszip.min.js`、`epub.min.js`。`scripts/prepare-vendor.js` 会在 `npm install` 和镜像构建时自动从 `node_modules` 复制它们。

打不开时的排查顺序：

1. 页面会先显示「正在打开…」，MOBI / AZW3 首次打开还会显示「先把 MOBI 转成可翻页的版本」。一直停在这句说明正在转换（大文件可能几十秒）。
2. 报「容器里没有找到 ebook-convert 命令」= 镜像里没装上 Calibre，重新 `docker compose pull` 拉带 Calibre 的镜像。
3. 报「转换失败：…」后面那截是 Calibre 的原话，通常是源文件加密（DRM）或损坏。
4. 报「这个文件打不开」= 文件本身不是标准 EPUB（加密、残缺，或其实是别的格式改了扩展名）。想看原文件的话，浏览器直接访问 `/api/book/<id>/file` 就是下载地址。

## 刮削规则

1. **优先读书籍内嵌元数据**：EPUB 读 OPF（书名、作者、语言、简介、封面），MOBI/AZW3 用 Calibre 的 `ebook-meta`，TXT 取第一行作标题。PDF 读文档属性——先找 trailer 指向的 Info 字典，缺失或损坏时读 XMP 的 `dc:title`，两者都没有才退回书签里最长的一条。PDF 里每个 `/Title` 都可能是书签，早先按第一个匹配取值会把封面后的「总目录」当成书名；现在只认文档属性。
2. **文件名兜底**：识别 `作者 - 书名`、`书名 (作者)`、`[作者] 书名`、`作者《书名》`、`《书名》01`（书名号包住书名、后面是册号）、Calibre 导出的 `书名_作者_年份` 等写法，末尾括号里的作者（如 `…大套装 (共16册) (陈磊 · 半小时漫画团队)`）会拆到作者栏，`(共16册)` 这类册数或版别说明留在书名里。`书名｜卖点文案` 这种书单导出名，卖点部分是乱码时只保留书名。
   内嵌元数据明显不可靠时以文件名为准：`版权信息`、`Unknown`、`!00001`、`\376\377…`、`SSReader Print.`（超星打印的默认值，作者常是 `wanqan`）、`CamScanner`、`扫描全能王`、`Microsoft Word - …` 这类值不会占据书名，只带分册号（如 `…中国史.1`）的也会改用文件名里的套装名。
   成套扫描书文件名只剩序号时，会用所在文件夹的名字补全：`【全宋诗】72册/01[652].pdf` → 「全宋诗 01」。只有当文件夹名形如「…72册 / …12卷」时才会这样推导，普通文件夹（如「小说」）不会把名字变成书名。
3. **封面**按优先级取：EPUB 内嵌封面 → PDF/MOBI/AZW3 由 Calibre 用 `ebook-meta --get-cover` 导出 → 书旁边同名的 `.jpg/.png` 图片 → 该目录下的 `cover.jpg`（一整个文件夹共用一张，适合《全唐诗》这类三十册一套的丛书）→ 渲染 PDF 首页（扫描版、加密版 PDF 没有内嵌封面，但首页通常就是封面或扉页）。都没有时按书名/作者生成一张字体封面（琥珀书脊 + 宋体书名）。

   补封面不用删索引：往目录里放 `cover.jpg` 或 `全唐诗 01.jpg` 后点一次「刮削」，没有封面的书会被重新处理一次并挂上，之后照旧秒过。
4. **增量刮削**：每轮扫描先只读文件的体积和修改时间，跟上一次的索引比对。体积、修改时间都没变、封面文件还在的书，**直接沿用上次结果，完全不解析、不调用 Calibre**；只有新增、改过、或上次刮出来是乱码的书才会真正刮一遍。所以往文件夹里放一本新书，一轮扫描通常只有那一本在跑。整轮没变化时连 `library.json` 都不重写。书架上方会显示「跳过 N 册未变化」，点「刮削」的提示里也会写明跳过了多少册、花了多久。想强制把整个书库重刮一遍，删掉 `data/library.json` 再点一次「刮削」即可。
5. **单本重刮**：书架封面左下角有个 `⋯`，点开是这本书的详情（格式、大小、路径、入馆时间、进度），里面有「重新刮削这本」。它和整库刮削不同——**完全不走增量判定**：先删掉这本书已缓存的封面，再像第一次遇到它那样重新解析文件、跑一遍 Calibre，刮完当场告诉你书名、作者、封面分别有没有变。遇到某一本书名乱码或封面不对，用这个修最省事，不用连累整个书库。

   对应接口是 `POST /api/book/:id/rescan`，同样可以用脚本批量调用。

   索引里每条 PDF 记录都带一个提取器版本号。刮削规则改版后（比如这次的 PDF 标题修复），旧记录会被识别出来重读一次，之后照旧秒过——所以升级后第一次「刮削」会慢一些，是在把 PDF 全部重读一遍，不是卡住了。

书架默认按 **书名升序** 排列，可切换 **文件名 / 最近添加 / 书名 / 作者 / 文件大小 / 格式**，升降序切换，格式筛选，以及书名/作者/路径搜索。排序前会把空格、标点、全半角统一掉再比，所以「全唐诗 01」和「全唐诗01」算同一个位置，一套书不会被打散；同名书之间再按文件路径排，卷次始终连贯。阅读进度保存在 `data/progress.json`。

## 配置项

在 `docker-compose.yml` 的 `environment` 里可改：

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `BOOKS_DIR` | `/vol1/1000/EBook` | 容器内默认书籍目录（你的电子书所在处） |
| `DATA_DIR` | `/app/data` | 索引、封面、转换缓存、进度 |
| `PORT` | `8080` | 监听端口 |
| `TZ` | `Asia/Shanghai` | 时区 |
| `SCAN_ON_START` | 未设置 | 强制指定"启动时是否刮削"，覆盖网页设置；设 `0` 关闭（首次无索引仍会刮） |
| `SCAN_INTERVAL_MINUTES` | 未设置 | 强制指定定时刮削间隔（分钟），覆盖网页设置；设 `0` 关闭定时 |

不设置这两项时，默认值（启动刮一次 + 每 60 分钟）只在首次使用生效，之后以网页 ⚙ → 自动刮削 里保存的值为准。

## 本地开发（不跑 Docker）

```bash
npm install
SCAN_ON_START=1 npm start
```

不带环境变量时，默认扫描项目内的 `demo-books/` 示例目录，索引写在 `data/`。本机没有 Calibre 时，MOBI/AZW3 会提示需要安装——Docker 镜像里已包含。

## 目录结构

```
night-library/
├── server/           扫描、刮削、转换、API
├── public/           书库界面与阅读器（含本地化的 pdf.js / epub.js）
├── demo-books/       本地预览用的示例书
├── data/             运行时生成：library.json / settings.json / covers / converted / backgrounds / progress.json
├── version.json      版本号（唯一来源，随代码打包进镜像）
├── Dockerfile
└── docker-compose.yml
```

## 设计说明

配色、字体和版式 token 在 `public/css/tokens.css`：深墨蓝 `#0B121C`、面板 `#111C29`、暖纸色 `#EDE6D8`、琥珀 `#E9A23B`。琥珀只用于「正在发生」的事——阅读进度、焦点、激活态。书库是夜读模式，阅读器默认是纸张模式（长时间阅读浅色更省眼），可一键切回夜读。
