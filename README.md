夜读是一个自托管的电子书管理与阅读系统：把 NAS 上的书籍文件夹挂进容器，它会自己读完书名、作者和封面，然后在浏览器里排成一座书架。不需要整理文件名，不需要导入书库，也不需要装客户端——加一本新书进文件夹，几分钟后书架上就出现了。

全部数据都在自己的机器上，书籍以只读方式挂载，刮削只读取、不修改原文件。从 3.7 起，网页里还能直接朗读电子书（选中一段文字就能从那里开始读，朗读时音乐自动暂停），并把任意一本转成 EPUB / TXT / DOCX / PDF 下载；3.8 补上了转换进度条、丛书默认按名称排序与拖动调整；3.9 把留言板提到左栏最上面，丛书分组不再因为书被收起而显示成 0 册，空置的分组满一小时会自己消失；3.10 把左栏那几块实心底板换成半透明玻璃（壁纸透得出来），并给留言同步加了「测试连接」和「补传未同步」；3.11 把留言同步换到自己的请求实现上，超时不再被 Node 自带的 10 秒上限截断，并且连 GitHub 只走 IPv4；3.12 让「测试连接」把 TCP 建连和 TLS 握手分开计时，并放大了左栏留言板的字号。

## 特性

| 分类 | 能力 |
| --- | --- |
| **刮削** | 增量扫描，只处理新增或改动过的文件；优先读书籍内嵌元数据，读不到再从文件名解析；封面多级兜底，实在没有就按书名生成一张 |
| **阅读** | PDF / EPUB / TXT / MOBI / AZW3 五种格式直接在网页里读，四种缩放、进度记忆、高亮、笔记、书签、朗读（设备自带语音，扫描版除外），笔记可导出 Markdown |
| **转换** | 任意一本转成 EPUB / TXT / DOCX / PDF 后直接下载，带进度条与预计剩余时间，A5 版式内嵌中文字体；AZW3 / MOBI 输出需要 Calibre，镜像未内置 |
| **组织** | 继续阅读、最近在读、阅读状态（未读 / 在读 / 读完）、隐藏、自动丛书（书名高频词成组）与手动分组（默认按名称升序，鼠标拖动可调整）、批量整理、阅读时长与 30 天统计，排序 / 筛选 / 搜索 |
| **留言** | 左栏留言板：昵称 + 邮箱 + 选填网址 + 算术验证码，留言同步到仓库 `messages/`，邮箱打码显示 |
| **音乐** | 顶栏 ⏮ ▶ ⏭ 直接控制嵌入的播放器（AnyListen 等），一键播放切歌；也支持 Subsonic 系（Navidrome / Airsonic / Gonic）随机播放 |
| **外观** | 四套配色主题（夜读 / 纸笺 / 墨影 / 青屿）× 四套字体风格（楷书 / 宋体 / 黑体 / 隶书）任意组合、自定义背景图与名称、文字可读性三档切换，桌面与手机自适应 |
| **部署** | 单个容器，镜像约 290 MB；不依赖外部数据库，索引、封面、进度都是 `data/` 下的 JSON 与图片 |

## 快速开始

三步跑起来，只需要 Docker 与 Docker Compose v2。

**1. 准备 compose 文件**

```bash
mkdir -p /vol1/1000/docker/night-library
cd /vol1/1000/docker/night-library
# 把仓库里的 docker-compose.yml 放到这个目录
```

**2. 指向自己的书库**

编辑 `docker-compose.yml`，把 `BOOKS_DIR` 改成 NAS 上真实的书籍目录：

```yaml
environment:
  BOOKS_DIR: /vol1/1000/电子书文件夹名
```

> [!NOTE]
> 默认值是镜像自带的 `demo-books`（3 本示例 txt）。没有改也能启动，书架上会先出现这几本示例书，不会因为路径不存在而报错。也可以在启动后进网页 ⚙ →「电子书文件夹」里添加。

**3. 启动**

```bash
docker compose pull && docker compose up -d
```

打开 `http://NAS地址:8421`，书架会自动开始刮削。

### 关于本文档里的路径与地址

下面的路径、IP、端口都是**示例值**，程序里没有写死任何一项，按自己的环境替换即可：

| 示例值 | 含义 | 说明 |
| --- | --- | --- |
| `/vol1/1000/电子书文件夹名` | 电子书存放目录 | 书放在哪就填哪 |
| `/vol1/1000/docker/night-library` | 项目目录（`docker-compose.yml` 所在层） | 目录名可自取，如 `ebooks` |
| `http://192.168.0.111:9500` | AnyListen 的服务地址 | 换成实际 IP 与端口 |
| `8421` | 宿主机对外端口 | 与其他服务冲突时改掉 |

> [!IMPORTANT]
> **书在一个目录，compose 文件在另一个目录。** 两者不要混放，否则扫描会把项目文件当成书库内容。

## 部署方式

<details open>
<summary><b>方式一 · 使用已构建的镜像（推荐）</b></summary>

镜像由 GitHub Actions 在推送后自动构建并发布到 GHCR，NAS 上只需要一个 `docker-compose.yml`，不需要源码：

```bash
cd /vol1/1000/docker/night-library
docker compose pull
docker compose up -d
```

`image:` 默认走南京大学镜像站前缀 `ghcr.nju.edu.cn/...`，内容和 `ghcr.io` 逐字节相同，国内拉取更快。想用官方源，把 `image:` 换成 `ghcr.io/rachavip/night-library:latest` 即可。

</details>

<details>
<summary><b>方式二 · 本地构建（不经过 GitHub）</b></summary>

把整个项目目录放到 NAS 上，用 `docker-compose.build.yml` 就地构建：

```bash
cd /vol1/1000/docker/night-library
docker compose -f docker-compose.build.yml up -d --build
```

国内网络拉包慢时，改用国内源版本：`Dockerfile.cn` 把 apt 指向阿里云、npm 指向 npmmirror，功能与默认版完全一致：

```bash
docker compose -f docker-compose.cn.yml up -d --build
```

需要带上 `Dockerfile.cn`、`docker-compose.cn.yml`、`package-lock.json`。

</details>

<details>
<summary><b>方式三 · 图形界面部署</b></summary>

飞牛 NAS：**Docker → 项目 → 创建项目**，项目路径选 compose 所在目录，compose 文件选 `docker-compose.yml`，点部署即可，效果与命令行一致。

</details>

### 更新

```bash
cd /vol1/1000/docker/night-library
docker compose pull && docker compose up -d
```

数据在 `./data` 与书库目录里，更新只换容器，不碰数据。页面右上角的版本徽标可以直接查看当前版本与更新说明。

> [!TIP]
> 推荐用 `&&` 串联命令：拉取失败时不会继续启动旧镜像，避免出现「看起来升级了、其实还是旧版本」的假成功。

### 版本与更新检测

主页副标题后有一个版本徽标，点开可看到更新日期、本次改动与「检查更新」。

- **版本号来源**：项目根目录的 `version.json`。页面显示与更新检查都读它，随代码打包进镜像，因此徽标显示的就是实际运行的代码版本。
- **自动提示**：打开页面后会在后台检查一次（30 分钟内不重复），发现新版本时徽标变为琥珀色并带圆点。
- **三种结果**：已是最新 / GitHub 上有新版本（需重新拉取镜像）/ 本机比 GitHub 新（改动尚未推送）。
- 检查先试 GitHub raw，失败再试 jsDelivr，两者都不可达时提示手动查看，不影响正常使用。

## 配置

`docker-compose.yml` 只保留必要项，逐项含义如下：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `image` | `ghcr.nju.edu.cn/rachavip/night-library:latest` | 镜像地址；换回官方源用 `ghcr.io/...` |
| `container_name` | `night-library` | 容器名，对应 `docker logs night-library`、`docker restart night-library` |
| `ports` | `"8421:8080"` | 宿主机 8421 → 容器 8080，8421 被占用就改冒号左边 |
| `/vol1:/vol1:ro` | — | 整个存储池只读挂入且路径一致，网页里填 `/vol1` 下任意目录都能刮到 |
| `./data:/app/data` | — | 索引、封面、转换缓存、格式转换产物、进度、笔记，跟随 compose 文件所在目录 |
| `restart` | `unless-stopped` | 开机与异常退出后自动拉起 |

环境变量：

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `BOOKS_DIR` | `/app/demo-books` | 默认书籍目录；改成实际书库路径，或在网页里增删 |
| `DATA_DIR` | `/app/data` | 索引、封面、转换缓存、进度 |
| `PORT` | `8080` | 容器内监听端口 |
| `TZ` | `Asia/Shanghai` | 时区 |
| `SCAN_ON_START` | 未设置 | 强制指定启动时是否刮削，覆盖网页设置；`0` 为关闭（首次无索引仍会刮） |
| `SCAN_INTERVAL_MINUTES` | 未设置 | 强制指定定时刮削间隔，覆盖网页设置；`0` 为关闭定时 |
| `MUSIC_URL` | 未设置 | 音乐服务地址，优先级高于网页保存值 |
| `MUSIC_MODE` | `embed` | `embed` 网页嵌入；`subsonic` 随机播放条 |

`SCAN_ON_START`、`SCAN_INTERVAL_MINUTES` 不设置时，默认「启动刮一次 + 每 60 分钟」只在首次使用生效，之后以网页 ⚙ →「自动刮削」里保存的值为准。

> [!NOTE]
> **关于 compose 顶层的 `name:`** —— 可以不写。不写时 Compose 的项目名取 compose 文件所在目录名，容器名由 `container_name` 决定，日常使用没有区别。仓库里 `docker-compose.build.yml`、`docker-compose.cn.yml` 两个变体保留了专用 `name`：它们靠 `-f` 指定，若与主文件同名项目，`up` 时会被当成同一个项目而互相替换容器。

### 挂载其他存储池

默认只挂载 `/vol1`。书籍在 `/vol2` 等其他存储池时，加一行挂载并重建容器：

```yaml
volumes:
  - /vol1:/vol1:ro
  - /vol2:/vol2:ro
```

## 使用指南

### 书房设置

点右上角 **⚙** 打开设置抽屉，改完点「保存设置」。

- **电子书文件夹**：增删要刮削的目录，添加时校验容器内能否访问，保存后自动刮削。移除文件夹并保存时，会一并清理该书目下的封面、转换缓存、进度、笔记、丛书归属、隐藏标记与阅读台账（电子书文件本身不受影响）。
- **名称**：系统名称与副标题，书架标题、页签、阅读器返回按钮同步更新。
- **主题**：夜读（墨蓝 + 琥珀，默认）、纸笺（浅色）、墨影（近黑 + 香槟金）、青屿（深青 + 薄荷绿）。
- **字体风格**：楷书通排（默认）、宋体书卷、黑体骨架、隶书骨架。只换字体族与字重，不动字号，所以切换不会让版面跳动；配色和字体各管一路，可以随意搭配。四套都只用系统自带字体，不下载任何字体文件；本机缺某个字体时自动退回相近的一种，设置里会在那张卡片上标出「本机无此字体」。
- **背景图片**：可上传本地图片，或填书籍目录里的相对路径（如 `壁纸/书房.jpg`）；暗度与虚化可调，暗度用于压暗背景保证文字可读。图片与窗口比例不一致时，铺满必然要裁掉一截，所以上传后会直接打开「调整取景」：框的比例就是窗口比例，按住图片拖动（或用方向键微调）把要保留的部分挪进框里，确认后保存即可；settings.json 里记的是 `background.focus`（两个 0–100 的百分比，默认 50/50 居中）。
- **文字可读性**：柔和阴影（默认）/ 清晰描边 / 不加效果三选一，设置里点一下就能预览，保存后生效。壁纸黑白反差大时「清晰描边」最稳；浅色主题自动换成白影。只作用于书房页面，不动壁纸和暗度滑块，也不影响阅读器里的排版。
- **音乐**：默认「网页嵌入」模式，给对应服务填地址即可，重启不丢。

### 自动刮削

往书库里放新书不用手动点「刮削」：

- **启动时刮一次**：默认开启。网页立刻可打开（先读上次索引），刮完书架自动刷新。
- **定时刮削**：默认每 60 分钟一次，书架上方显示「每 60 分钟自动整理 · 下次 HH:MM」。
- **调整无需改 compose**：⚙ →「自动刮削」里改开关与分钟数，保存即生效；间隔填 `0` 关闭定时。
- 手动与自动刮削共用一把锁，不会重叠执行；完成后会提示新增册数。
- 单轮没有变化时连索引文件都不重写；书架上方会显示「跳过 N 册未变化」。

### 音乐

支持两种模式，在 ⚙ → 音乐 里切换。

**网页嵌入（默认）**：把 AnyListen、music-dl、Songloft、MelodyHub、Solara 光域的地址填进去，播放器在面板里嵌入显示，左上角可一键切换服务。顶栏的 ⏮ ▶ ⏭ 直接映射到播放器底部按钮——**点播放就开始，不用先打开面板**，切歌、暂停同理。

服务通过同源反向代理转发（HTTP 与 WebSocket），因此跨域、`X-Frame-Options` 之类的问题在服务端就被处理掉了；代理地址从设置里动态读取，不写死任何 IP。

<details>
<summary><b>顶栏按钮不出声？先确认这几个前提</b></summary>

顶栏按钮本质上是「代点播放器里的按钮」，所以播放器本身得先有歌可放：

1. **先登录一次**：第一次点播放会弹出面板，在面板里输入服务密码。登录状态由浏览器保存，同浏览器只需登录一次；换浏览器或清缓存需重新登录。
2. **确认服务里有能播的歌**：直接打开服务地址，点页面底部的播放键试试。那里放不出声，顶栏按钮也一样——属于音源问题。
3. **多收藏几首**：列表太短，或收藏曲目音源失效（下架、版权限制），都会导致播到一半就停。
4. **循环方式选持续播放的一种**：随机播放 / 单曲循环 / 列表循环，不要选「播完最后一首就停」。
5. **音源与收藏归音乐服务管理**：夜读只负责把按钮映射过去，不管理曲库。

</details>

**随机播放（Subsonic）**：兼容 Navidrome、Airsonic、Gonic 等。填 `IP:端口`（不用写 `http://`）、用户名与密码；密码只保存在容器内 `data/settings.json`，接口返回时打码。由服务端代理请求，浏览器不直连，避开跨域；一次随机取 50 首打乱播放，支持上一首 / 下一首 / 暂停 / 音量，放完自动接下一首。

> [!NOTE]
> 若本站启用 HTTPS 而音乐服务仍是 HTTP，浏览器会因混合内容拦截嵌入页——两边保持同为 HTTP，或给音乐服务也配 HTTPS。

### 格式支持

| 格式 | 阅读 | 可导出为 | 说明 |
| --- | --- | --- | --- |
| PDF | ✅ | EPUB / TXT / DOCX | pdf.js 逐页渲染，四种缩放：匹配宽度 / 匹配页面 / 匹配可见 / 实际大小 |
| EPUB | ✅ | TXT / DOCX / PDF | epub.js 渲染，章节跳转与字号调整 |
| TXT | ✅ | EPUB / DOCX / PDF | 自动识别 UTF-8 / GB18030，按视口重新分页 |
| MOBI | ✅ | EPUB / TXT / DOCX / PDF | 由镜像内置的 KindleUnpack 解包为 EPUB 后阅读，结果缓存 |
| AZW3 | ✅ | 同上 | 同上 |

MOBI / AZW3 的转换只发生在首次打开时，产物写在 `data/converted/`，原始书籍始终以只读方式挂载，不会被修改。

### 格式转换

书籍详情（封面左下角 `⋯`）底部有一排「转为其他格式」，点一下就在服务端转换并**直接下载**，不写回书库——写回去会让下次扫描多出一条重复书目。产物缓存在 `data/transformed/`，同一本书同一个目标格式只转一次，源文件改动后自动重转。

- 章节切分优先用源文件自带的章节标记（EPUB 的 spine 与 `toc.ncx`、DOCX 的标题样式）；没有标记的（整篇 TXT、文字层连续的 PDF）按「第 X 章」这类行文标题切，再不行就按段落长度与固定页数分段。
- PDF 用 A5 版式、10.5pt 正文、页码居中，内嵌 Debian 自带的 Droid Sans Fallback 中文字体（Apache-2.0）。嵌入的是完整字体而不是子集，所以每本约 3–5MB——不嵌的话中文会整片空白，各阅读器又不保证自带中文字体。
- **转为 AZW3 / MOBI 需要 Calibre**，镜像为控制体积没有内置（见下方「镜像体积」说明），这两个按钮在界面上是置灰的，鼠标停留会写明原因。Kindle 官方的 Send to Kindle 已直接收 EPUB / DOCX / PDF / TXT，这四种足够用。
- 扫描版 PDF（没有文字层）转不了，会提示「抽不出字来」而不是给一个空文件；DRM 加密的 EPUB / MOBI 同样会被拒。
- 转换结果只含文字，源文件里的插图、图表不会带过去。
- 转换中浮出进度条：PDF 按页、其它格式按章上报进度，并按已用时间估算剩余时间；几百页的大书也能看到进度在走。命中缓存时转换不到一秒，面板不会出现，省得闪一下。

<details>
<summary><b>实现细节与排查</b></summary>

EPUB / MOBI / AZW3 统一通过带 `.epub` 后缀的地址交给 epub.js（`/api/book/:id/read.epub`）。epub.js 靠 URL 后缀判断「压缩包」还是「已解压目录」：无后缀时它会当成目录去请求 `META-INF/container.xml`，从而打不开。另外 epub.js 不自带解压器，页面必须有全局 `JSZip`，因此 `public/vendor/` 下四个文件缺一不可：`pdf.min.js`、`pdf.worker.min.js`、`jszip.min.js`、`epub.min.js`，由 `scripts/prepare-vendor.js` 在安装与构建时自动生成。

打不开时的排查顺序：

1. 停在「正在打开…」说明仍在转换，大文件可能几十秒。
2. 提示「容器里缺少 python3」= 镜像版本过旧，重新 `docker compose pull`。
3. 提示「转换失败：…」后面是解包器原话，多为源文件加密（DRM）或损坏。
4. 提示「这个文件打不开」= 文件不是标准 EPUB（加密、残缺，或改过扩展名）。原始文件可从 `/api/book/<id>/file` 下载。

### 阅读器

| 操作 | 效果 |
| --- | --- |
| 鼠标滚轮 | 翻页；一格一页，快速滚动连续翻页。页面高于窗口时先滚到页底再翻页 |
| 底部「首页 / 末页」 | 跳到第一页 / 最后一页；EPUB 对应第一章 / 最后一章 |
| 底部页码框 | 输入页码回车跳转，越界自动修正（仅 PDF / TXT） |
| 底部滑块 | 拖到任意进度 |
| ← → / PageUp PageDown / 空格 | 上一页 / 下一页 |
| Home / End | 首页 / 末页 |
| 选中文字 | 浮出「高亮 / 写笔记」；高亮按 CFI 记录，换字号不跑位，TXT 按页码 |
| 顶栏「🔊 朗读」 | 用设备自带的语音把这一页读出来，读完自动翻页接着念；播放条上有暂停、上一句 / 下一句、语速与音色 |
| 选中文字 →「从这里读」 | 从选中的那一句开始念，不用回到页首 |
| 朗读时音乐 | 书架上的音乐自动暂停，两个声音不会叠在一起 |
| 顶栏「笔记」 | 右侧面板汇总高亮、笔记与书签，点击跳回原处，可导出 Markdown |
| 面板「＋ 加书签」 | 记住当前位置（PDF / TXT 按页码，EPUB 按 CFI） |
| `Esc` | 关闭阅读器标签页 |

翻页后自动回到新页顶部；改缩放方式时保持当前页与滚动位置。阅读进度写入 `data/progress.json`，下次打开回到上次位置。

**朗读**用的是浏览器 / 系统自带的语音合成，不用装任何东西，也不上传书的内容。因此：

- 音色取决于设备。Windows 一般自带「Microsoft Huihui / Yaoyao」，macOS 与 iOS 有「婷婷」，安卓视系统而定；列表里只列中文语音，没有中文声音时会提示先去系统设置里装一个。
- **只支持有文字层的书**。PDF 用 pdf.js 的文本层取字，EPUB 读章节 HTML，TXT 直接读文本，MOBI / AZW3 转换后同 EPUB。**扫描版或纯图片 PDF 没有文字层**，点朗读会提示「这本书是图片或扫描版，没有可提取的文字」，不会假装在读。
- 朗读时请让阅读器标签页保持在前台。浏览器会暂停后台标签页的语音，切回来会从当前句接着念。
- 语速（0.6–1.8 倍）与音色记在浏览器本地，换设备要重选一次。朗读位置不写入阅读进度——进度仍以手动翻到哪一页为准。

### 继续阅读、隐藏、丛书与统计

首页分左右两栏：左侧最上面是留言板入口，往下是导航（藏书状态、丛书）与「继续阅读 / 最近在读 / 阅读记录」，右侧是格式筛选与书架。左栏高度超过屏幕时会自己滚动，丛书再多也不至于把「阅读统计」这些压到视口外面。窄屏（≤1000px）时左栏变成书架上方一整块，导航改为横向排列，不设高度上限。

| 功能 | 说明 |
| --- | --- |
| 继续阅读 | 取进度 1%–97% 且最近打开过的书，按时间倒序，显示封面、进度与读到哪 |
| 阅读状态 | 未读 / 在读 / 读完；翻到 98% 以上自动算读完，也可手动标记 |
| 隐藏 | 不常看的书收起来，书架默认不显示，文件与进度都保留；点顶部格式条最右侧的「隐藏」只看它们（左栏不再重复放一个入口） |
| 丛书 | 书名里出现 5 次以上的词自动归成一套（如「西游记」「二十四史」），也可手动建组；一本书可归属多组，丛书与格式条一次选一堆 |
| 批量整理 | 顶栏「整理」勾选或用鼠标在书架上拖框选中，可一次隐藏、取消隐藏；「加入丛书」保留原有归属，「移动到丛书」只留选中的那一组 |
| 阅读统计 | 今天 / 本周 / 今年时长、连续天数、30 天柱状图、最常翻的书、最近读完 |
| 笔记 | 每本书独立，按 CFI 或页码锚定，重复选同一段会合并 |

顶部格式条最前面的「全部（不含隐藏）」与书架默认视图**不含已隐藏的书**；页面左上角的「藏书 N 册」是**书库总量**，含收起的书——收起只是不让它占地方，没把书从书库拿走。收起了多少，看格式条右端「隐藏」后面那个数，页面上不再重复写一遍。

**每一栏的数字就是点下去会看到的册数**：左侧「在读」「读完」「丛书」和顶部格式条换的都是同一层「现在看这一堆书」，一次只选一堆——点丛书就只看这一套的全部（不按格式再拆一次数），点 EPUB 就只看整柜的 EPUB，之前选中的丛书自动让出来；再点同一个就回到「全部」。顶栏最前面的「全部（不含隐藏）」是总闸，点了把丛书、状态、格式、搜索一起归零。换堆时搜索框会被清空，免得按钮上的数和点进去的册数对不上。「在读」「读完」的册数不含已隐藏的书，和书架看到的一致。丛书分组是例外：组里有几本就写几本，收起与否都算，点进去也看得到收起的书（封面压暗、左下角标「已收起」），所以不会出现「组名 0 册、点开空无一物」。只有左上角「藏书 N 册」是总量。

**收起一本书**：把鼠标移到封面上，点右下角 `⋯` 打开详情，点「隐藏」即可；再打开同一本书的详情会变成「取消隐藏」。

**收起一批书**：在书架空白处（或任意卡片上）按住左键拖动，拉出一个琥珀色选框，框到的书会立刻勾选，松手后底部浮出操作条，点「隐藏」即可。也可以点顶栏「整理」手动逐本点选，或用「全选 N 本」一次选完当前列表——搜索关键词之后点全选，就是「把这批书一起处理」。

**自动丛书**：不用先建组。书库里同一个词组出现在 5 本以上的书名里，左侧「丛书」下就会多出一条，点进去就是这一套。`西游记`、`西游记（上下册）`、`西游记 第03卷` 都会落进同一个组；`西游` 这种被更长词组几乎全覆盖的碎片会被自动丢掉，`全集`、`上册`、`修订版` 这类版次词和 `中国`、`小说` 这类泛词也不会成组。

- 组名就是书名里的那个词，觉得太素可以把鼠标移到条目上点 **✎** 改名，只换显示、不改归组规则。
- 条目默认按名称升序排列（中文按拼音）；用鼠标拖动可以调整顺序，松手后自动保存。之后扫描新出现的组会按名称补在末尾，不会插进你排好的顺序里。
- 点条目上的 **×** 是「不再显示这一组」，书不会少；组头的 **↺ 恢复 N** 再放回来。
- 同名合并（把自动组并进手动组）不会产生「恢复」入口：那是有意的整理，不需要后悔药；旧版本留下的这类计数升级后会自动清掉。
- 一个组一本都点不出来就不再留着：手动建的空组有 1 小时宽限期往里放书，空置满一小时自动删除，界面上会自己少一条（页面每 10 秒核对一次条数）。计时从「发现它空了」那刻算，不追溯建组时间。
- 丛书和格式条二选一：点丛书看整套，点格式看全库该格式，两者不叠加——按钮上的册数才总是准的。

### 留言板

左栏最上面（「藏书」组名之上）有「留言板」入口，点开是一个抽屉。按博客评论框的样子排：留言框在最上面（里面的引导语点一下就消失，直接能写），中间一条是「防机器人验证 + 提交评论」，下面并排**昵称(必填)、邮箱(必填)、网址**。验证码一次性、五分钟过期，同一个 IP 一分钟最多三条，用来挡住乱刷的机器人。

- 留言先写进 NAS 的 `data/guestbook.json`（网页列表从这里读），再逐条写进 GitHub 仓库的 `messages/` 文件夹，一条留言一个 Markdown 文件。
- **仓库是公开的，留言内容任何人都能看到**。邮箱在网页列表和 GitHub 文件里都做了打码（前几位隐藏，只留后三位和域名），完整邮箱只留在 NAS 本地的 `guestbook.json` 里。
- 「网址」是选填的，填了必须以 `http://` 或 `https://` 开头，否则会被拒绝——避免有人塞一条点开就执行脚本的假链接。列表里显示成外链，去掉协议头、过长截断。
- 要在设置 →「留言板同步」里填一个有仓库写权限的 GitHub 个人访问令牌才会同步；令牌只存 `data/settings.json`，不进镜像、不回显到页面上。没填令牌时留言照常发表，只存本机，条目上会标「只存本机」。
- GitHub 暂时连不上也不会丢留言：本地先落盘，失败会在结果里写明原因。现在的原因会具体到「连接失败（ECONNRESET）」「401 Bad credentials」这一级，不再是笼统的「超时」。
- 同步走自己的请求实现（`https.request`，只走 IPv4，15 秒上限），不用 Node 自带的 `fetch`。原因是 `fetch` 底层把「建立连接」硬限成 10 秒，比我们设的上限还早生效，报 `UND_ERR_CONNECT_TIMEOUT` 时看着像连不上，实际只是握手慢。若长时间卡在这里，多半是 docker 网桥 MTU 与实际线路不一致，可给 compose 的默认网络把 MTU 降到 1400。
- 同步卡住时用设置里的**测试连接**：从 NAS 里试一次，并把「域名解析到哪些地址」「TCP 连上用了多久」「TLS 握手用了多久」「令牌能不能读仓库」分开报。**看 TCP 和握手这两个数就能定位**：
  - TCP 通了、握手一直不完成 → 能到 GitHub，但加密握手过不去。宿主机 `curl` 却很快时，基本是 docker 网桥 MTU 比实际线路大（家宽 PPPoE 是 1492，网桥默认 1500），大包被丢、握手反复重传。给 compose 加一段把 MTU 降到 1400 即可：
    ```yaml
    networks:
      default:
        driver_opts:
          com.docker.network.driver.mtu: "1400"
    ```
    追加到 `docker-compose.yml` **末尾**（顶格，和 `services:` 同级），然后 `docker compose up -d` 重建网络，再点一次「测试连接」。
  - TCP 都没连上 → 容器出网被拦。宿主机通、容器不通时，可改用 `network_mode: host`（此时要删掉 `ports:`，并把 `PORT` 直接设成想用的宿主机端口），或给容器配代理。
- **先留言、后填令牌**时，那时候提交的留言只会存在本机，之后再没人碰过它。设置里的**补传未同步（N 条）**会把它们逐条补推上去，第一条失败就停；保存令牌时也会自动补传一次，跑在响应之后，不会拖慢保存按钮。
- 留言提交不会触发镜像重建：构建 workflow 已排除 `messages/**`。

**手动建组**：左侧「丛书」组头 **＋ 新建**，或在书籍详情里给单本勾选；也可以搜索关键词 → 顶栏「整理」→「全选 N 本」→「加入丛书」→ 新建并加入，组名会预填成搜索词。手动组和自动组在左侧并列显示（自动的在前），手动建的不受书名影响，成员完全由你决定。

**加入还是移动**：两个按钮挨在一起，区别只有一处。
- 「加入丛书」保留书原来的组，一本书可以同时属于几组，适合「历史」与「通史」这种交叉。
- 「移动到丛书」先把书从其它手动组里移出，再放进选中的那一组，只列已有的组，不给新建，适合把书从「待读」挪到「在读」。

**同名就是合并，不会再开一组**：在「加入丛书」里输入的新名字如果已经存在，不会多出一个重名条目，而是直接并进原来那一组；输入框下方会先提示「已有「X」分组（N 本）」，让你知道点下去会发生什么。撞上的是自动组时，会先问一句——合并后那一组转为手动维护，按书名自动归组不再生效，原有成员一起保留。

**改名撞名也合并**：把一组改成另一个已存在的组名时，会提示「已有「X」分组，共 N 本」，确认后两组合成一个，书一本不少，被并掉的那组不再单独存在；取消则什么都不改。

**老数据里的重名会自己收起来**：启动时、每次扫描后各检查一遍，同名（忽略空格与大小写）的分组只留一条——手动组活下来，自动组算出来的书并进去，册数取并集；该关键词同时收起，扫描时不会再长出一个同名副本。所以升级后不会再出现两个「西游记」。

阅读时长只统计「标签页可见 + 最近 5 分钟内有操作」的时间，每分钟上报一次，切走时补发，所以页面开着过夜不会记成整夜。

数据文件（删掉即清空，不影响书籍与进度）：

- `progress.json` — 位置、进度、状态、读完时间
- `reading.json` — 按天累计的阅读秒数与每本书时长
- `collections.json` — 手动建的丛书与成员
- `series.json` — 自动丛书的两项人工设定：改过的组名、收起的组名（组本身每次扫描重算，不存成员）
- `hidden.json` — 已隐藏的书 id
- `notes.json` — 高亮、笔记、书签

相关接口：`/api/reading/summary`、`/api/reading/ping`、`/api/collections`（`POST` 同名即合并）、`/api/collections/:id/move`（移动到该组）、`/api/collections/merge`（两组合并）、`/api/series/restore`、`/api/books/hide`、`/api/book/:id/notes`、`/api/book/:id/status`、`/api/taste`（看记了哪些搜索词）、`/api/taste/log`（记一次搜索）、`/api/taste/reset`（清空记录），笔记导出为 `/api/book/:id/notes/export`（Markdown）。

## 刮削规则

<details>
<summary><b>点开查看完整的元数据、封面与文件名处理逻辑</b></summary>

**1. 优先读书籍内嵌元数据**

EPUB 读 OPF（书名、作者、语言、简介、封面）；MOBI / AZW3 直接解析 PalmDB 头与 EXTH 记录（`server/mobi.js`）；TXT 取第一行作标题，但只认「像标题」的第一行（不超过 24 字、不含逗号句号顿号），否则回退文件名；PDF 读文档属性——先找 trailer 指向的 Info 字典，缺失时读 XMP 的 `dc:title`，都没有才退回书签里最长的一条。PDF 里每个 `/Title` 都可能是书签，只认文档属性可避免把「总目录」当成书名。

内嵌元数据明显不可靠时以文件名为准：`版权信息`、`Unknown`、`!00001`、`SSReader Print.`、`CamScanner`、`扫描全能王`、`Microsoft Word - …` 这类值不会占据书名。

**2. 文件名兜底**

识别 `作者 - 书名`、`书名 (作者)`、`[作者] 书名`、`作者《书名》`、`《书名》01`、Calibre 导出的 `书名_作者_年份` 等写法。末尾括号里的作者（如 `… (陈磊 · 半小时漫画团队)`）拆到作者栏，`(共16册)` 这类册数说明留在书名里。

成套扫描书文件名只剩序号时，用所在文件夹名补全：`【全宋诗】72册/01[652].pdf` → 「全宋诗 01」。仅当文件夹名形如「…72册 / …12卷」时才会这样推导。

**3. 封面按优先级取**

EPUB 内嵌封面（OPF 未声明时在压缩包里找 `cover.*`）→ MOBI / AZW3 由 EXTH 封面索引取图 → 书旁同名 `.jpg/.png` → 目录下的 `cover.jpg`（整套丛书共用一张）→ 渲染 PDF 首页（扫描版、加密版 PDF 没有内嵌封面，但首页通常就是封面）→ 都没有时按书名 / 作者生成字体封面。

补封面不用删索引：放入 `cover.jpg` 或 `某套书 01.jpg` 后点一次「刮削」，缺封面的书会被重新处理一次。

**4. 增量刮削**

每轮先只比对文件体积与修改时间，再检查封面文件是否还在。三者都没变的书直接沿用上次结果，**完全不解析文件**；只有新增、改动或上次刮出乱码的书才真正跑一遍。整轮无变化时不重写 `library.json`。想整库重刮，删掉 `data/library.json` 再点一次「刮削」。

**5. 单本重刮**

封面左下角 `⋯` 打开书籍详情（格式、大小、路径、入馆时间、进度），底部「转为其他格式」那一排按钮见上方「格式转换」小节。其中「重新刮削这本」**不走增量判定**：删除该书缓存封面后重新解析，并当场对比书名、作者、封面是否变化。对应接口 `POST /api/book/:id/rescan`，可用脚本批量调用。

索引里每条 PDF 记录带提取器版本号，解析规则升级后旧记录会自动重读一次，因此升级后首次「刮削」偏慢属于正常。

</details>

书架默认按**猜你想看**排序：书名里反复出现的词越热，含这个词的那一类书越靠前（八百本里有两百本《红楼梦》某回，它们就在最前面）。另外还有**最近添加 / 书名 / 作者**三种，都支持升降序，以及格式筛选与书名 / 作者 / 路径搜索。排序前会统一空格、标点与全半角，因此「某套书 01」与「某套书01」位置一致，同一套书不会被拆散。

「猜你想看」还会把**搜过的词**算进去：同一个词搜得越多，书名或作者沾边的书越往前提，同属一个词组的相关书拿四成分。记录只存在本地 `data/searches.json`，只记词与次数（不记你打开了哪本书），在设置里能看到记了什么、也能一键清空。

## 常见问题

<details>
<summary><b>拉取镜像报 503</b></summary>

国内镜像站是第三方代理，偶发整站 503（连 `/v2/` 根路径都打不开，说明是它自己挂了）。此时**不要反复 `down`**，容器删掉后就只剩空网络：

```bash
docker compose up -d                       # 先用本地现成镜像把服务拉起来
docker compose pull && docker compose up -d  # 等一两分钟再试
```

仍失败可换 `ghcr.1ms.run`，它和官方 GHCR 返回同一个 digest，镜像内容逐字节一致：

```bash
docker pull ghcr.1ms.run/rachavip/night-library:latest
docker tag ghcr.1ms.run/rachavip/night-library:latest ghcr.nju.edu.cn/rachavip/night-library:latest
docker compose up -d
```

</details>

<details>
<summary><b>页面版本与镜像版本不一致</b></summary>

版本徽标读的是 `version.json`，只能证明这一个文件是最新的。静态文件是否同步，用字节数比对最准（静态文件未压缩，大小应完全相同）：

```bash
wc -c public/css/library.css                      # 本地
curl -s http://NAS地址:8421/css/library.css | wc -c  # 运行中的服务
```

两个数字不同，说明有文件没更新到运行环境。

</details>

<details>
<summary><b>书架只有 3 本示例书</b></summary>

说明 `BOOKS_DIR` 仍指向镜像自带的 `demo-books`，或 `data/settings.json` 里的 `folders` 为空。进 ⚙ →「电子书文件夹」添加真实书库路径并保存即可；`settings.folders` 的优先级高于 `BOOKS_DIR`。

</details>

<details>
<summary><b>音乐面板打不开或嵌入被拒绝</b></summary>

部分站点用 `X-Frame-Options` 或 CSP 禁止被嵌入，测试时会提示「嵌入受限」，播放器顶部同时提供「新窗口打开」作为兜底。连接超时会显示明确错误并自动重试两次；也可以直接打开音乐服务的地址，确认它本身可访问。

</details>

## 本地开发

```bash
npm install
SCAN_ON_START=1 npm start
```

不带环境变量时默认扫描项目内的 `demo-books/`，索引写入 `data/`。MOBI / AZW3 的解包需要本机有 `python3`（Windows 可用 `PYTHON_BIN` 指定解释器），缺失时只影响这两种格式的在线阅读，其余功能正常。

镜像只装三样东西：`python3`（跑 KindleUnpack）、`poppler-utils`（用 `pdftoppm` 渲染 PDF 首页当封面）与 `fonts-droid-fallback`（PDF 导出时内嵌的中文字体），合计约 35MB。元数据解析、格式读取与四种格式的写出都由项目内代码完成，因此不需要 Calibre——Calibre 会带回约 712MB 的 Qt6 + WebEngine，这也是镜像能压到约 290 MB 的原因。

代价是**转不出 AZW3 与 MOBI**：Linux 上只有 Calibre 的 `ebook-convert` 会写 PalmDB / KF8，Amazon 的 kindlegen 2017 年就停止分发、也没有可再分发的替代品。界面保留这两个按钮但置灰并写明原因，需要的话在自己的机器上用 Calibre 转一次即可。

## 设计

配色、字体与版式 token 集中在 `public/css/tokens.css`：深墨蓝 `#0B121C`、面板 `#111C29`、暖纸色 `#EDE6D8`、琥珀 `#E9A23B`。琥珀只用于「正在发生」的事——阅读进度、焦点、激活态。书库是夜读模式，阅读器默认纸张模式（长时间阅读浅色更省眼），可一键切回夜读。四套字体风格也在同一个文件里，`data-typeface` 分别覆盖 `--f-*`（字体族）、`--w-*`（字重）、`--ls-*`（字距）三组变量，所以加一套新风格只要再加一个 `:root[data-typeface="…"]` 块。

镜像构建时会执行 `scripts/obfuscate.js`，把 `server/` 与 `public/js/` 就地换成混淆版本，因此从镜像里取出的代码难以直接阅读；仓库中保存的始终是可读源码。混淆只是抬高阅读成本，前端代码最终仍会下发到浏览器，无法阻止有心人逆推。
